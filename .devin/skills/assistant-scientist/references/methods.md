# Working methods of great scientists

Use these as reasoning tools. Pick the one that fits the problem and apply it silently. Name the scientist only when the method itself is what the user needs to learn.

## Contents
- Method table
- When to use which
- Additional names to draw on

## Method table

| Method | Origin | How to apply |
|---|---|---|
| Reduce to axioms, derive consequences, compare with data | Newton | State the minimum set of assumptions. Derive what follows. Check against measurement. |
| Compute explicitly, many cases, then generalize | Euler | Work three or four concrete examples by hand before stating a general rule. |
| Few results, fully ripe; verify numerically | Gauss | Do not present a result until it is checked by an independent route, ideally a numeric one. |
| Analogy that carries mathematical structure | Maxwell | Map the unknown system onto a known one with the same equations. State where the analogy breaks. |
| Thought experiment from principles | Einstein | Pose an idealized scenario that forces a contradiction or a consequence. Start from invariance and symmetry. |
| Limiting cases and dimensional analysis | Rayleigh, Einstein, Taylor | Take every parameter to 0 and infinity. Check units. A formula that fails limits is wrong. |
| Order-of-magnitude estimation | Fermi | Estimate with round numbers before any detailed calculation. Reject plans that miss by many orders. |
| Symmetry implies conservation | Noether | Ask what is invariant. Use it to find conserved quantities and constrain the answer. |
| Explain it simply or you do not understand it | Feynman | Write the explanation for a first-year student. Any gap shows what is not understood. |
| Information and noise as the core quantity | Shannon | Define the signal, the channel and the limit. Ask what the maximum possible is. |
| Computability and what a procedure can do | Turing | Ask whether the problem is decidable, and what its complexity class is, before designing a solution. |
| Separate the formalism from its interpretation | Schrödinger, Dirac, von Neumann | State the mathematical structure exactly, then state separately what it is claimed to mean. |
| Mentally build and run it, then test physically | Tesla | Simulate the design fully in thought or code. Do not skip the physical or numerical test; untested designs are hypotheses. |
| Experiment decides | Faraday | Design the simplest experiment that distinguishes the hypotheses. |
| Falsify, do not confirm | Popper (method), Michelson-Morley (example) | Find the result that would prove the idea wrong, then look for it. |
| Prove it or find the counterexample | Euclid, Hilbert, Gödel | State the claim exactly. Try to prove it. Where the proof stalls, construct the counterexample there. |

## When to use which

- New idea or claim: limiting cases, Fermi estimate, falsification, symmetry.
- Hard derivation: Euler (examples first), then Gauss (independent check).
- Confusing concept: Feynman (explain simply), Einstein (thought experiment).
- Modeling a system or simulation: dimensional analysis, limiting cases, Maxwell analogy, Noether (conserved quantities as validation checks for a simulation).
- Algorithms and computation: Turing, Shannon.
- Experimental or engineering design: Faraday, Tesla (with mandatory testing).

## Additional names to draw on

Use methods from any of these when relevant: Archimedes, Galileo, Kepler, Fermat, Leibniz, Lagrange, Laplace, Fourier, Cauchy, Riemann, Galois, Cantor, Poincaré, Hamilton, Boltzmann, Gibbs, Planck, Bohr, Heisenberg, Pauli, Born, Dirac, Fermi, Wigner, Curie, Hilbert, Noether, Kolmogorov, Wiener, Ramanujan, Hardy, Landau, Feynman, Dyson. Do not claim a method belongs to a scientist unless you are confident of the attribution; if unsure, state the method without attribution.
